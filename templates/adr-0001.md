# HTML-first blocks with Tailwind for new work

We need faster, safer block creation than hand-writing AEM `_json` / `js` / `css` and keeping them in sync. We adopt an HTML-first toolchain: developers edit a Block Source (`blocks/{name}/{name}.html` with `data-*` markers and Tailwind), `aem:generate-block` scaffolds that source (simple `heading` + `text` fields, labels in the project language, kebab-normalized name) plus a Draft, then calls Block Build. Block Build derives Generated Artifacts (committed, read-only), syncs Draft authored cells from Block Source field defaults, plus section registration, gated by a custom Source Gate (data-* contract limited to `text`/`richtext`/`reference`, at least one heading, img alt, field labels). `aem:up` runs the AEM CLI alongside `aem:watch` so Block Source edits rebuild and refresh preview in near realtime. Tailwind is mandatory only for new HTML-first blocks; Legacy Blocks remain valid. Bootstrap is idempotent: the toolchain lives in the versioned `aem-kit` package (public GitHub repo, installed over HTTPS, so neither CI nor developers need credentials), applied to each repository created by Cloud Manager from the xwalk boilerplate with `aem-kit init`, driven by `aem-kit.config.json` (project name, language, font and Tailwind tokens). The same package runs the pre-commit check (build, ESLint, Stylelint, Prettier, html-validate, axe) and the CI check.

## Considered Options

- **Vanilla AEM boilerplate only** (hand-written JS/CSS/models) — rejected for new blocks: too much boilerplate and easy model/DOM drift.
- **Migrate every Legacy Block to HTML-first** — rejected for now: high cost, no immediate need; coexistence is enough.
- **axe / html-validate on every build** — rejected: slower feedback while editing; they run in the pre-commit check and CI instead of on each Block Build.
- **Copying `tools/` into every repository** — superseded: copies drift; a versioned package is updated by re-running `aem:init`. Repositories cannot start from a custom template because Cloud Manager always creates them from the boilerplate.
- **axe only in CI** — rejected: the team wants feedback before the commit; static checks plus axe on the affected Drafts run in the pre-commit, and CI repeats them for `--no-verify`.
- **Reserved block name denylist** — rejected: only refuse when the block path already exists; authors own naming collisions with default content.
- **Draft only on generate** — superseded: Draft authored cells sync from Block Source on every Block Build so local preview stays aligned.
